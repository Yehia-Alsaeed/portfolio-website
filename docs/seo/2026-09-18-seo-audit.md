## 1. Executive summary

### What is already good

The technical foundation is unusually clean for a portfolio site:

- Every public route sets a title, meta description, and canonical URL. Production Lighthouse SEO scores 100 on mobile (re-verified today).
- `robots.txt` and `sitemap.xml` are generated from code, point at the correct Production origin, and the sitemap `lastmod` values come from real git history.
- Dynamic 1200x630 Open Graph images exist for all 8 routes and Twitter card tags are emitted.
- Person JSON-LD on the homepage and OfferCatalog JSON-LD on `/services`.
- Fully static prerendering (`X-Nextjs-Prerender: 1`), CDN cached, 79 KB HTML, self-hosted 43 KB font subset, no third-party scripts except Vercel Analytics. CLS 0 in CI.
- Full security header set, `/admin` correctly `noindex`, real 404 status on unknown slugs, trailing-slash 308 redirect, no `X-Robots-Tag: noindex` leaking to Production.
- The projects grid is server-rendered (all 17 cards are in the HTML), so nothing important is hidden behind client JavaScript.

### What is blocking rankings

1. **The site is effectively invisible in search.** A `site:yehia-alsaeed.vercel.app` query returns nothing on Bing and the US Google index used by the search tool. Searching the exact name `"Yehia Alsaeed"` returns other people. Either the site has never been submitted to Google Search Console / Bing Webmaster Tools, or it was indexed and dropped. This is the first thing to fix and it is not a code change.
2. **Production is stale.** The live site still serves the recruiter-first copy (title "Yehia Alsaeed | AI/ML Engineer and Web Developer", services h1 "I build stores & software that ship."). The client-first rewrite with the target phrase in the title, description, h1 area and OG image is entirely uncommitted on `dev` (23 modified files, 7 untracked). The sitemap `lastmod` dates on Production are 2026-08-17/18. None of the SEO copy work has shipped.
3. **Zero backlinks and zero entity signals.** No client site credits Yehia, the GitHub profile "website" field is empty, the GitHub profile README does not link to the site, there is no Google Business Profile, no directory listings. A new site with no links does not rank for commercial queries regardless of on-page quality.
4. **Free `*.vercel.app` subdomain.** `vercel.app` is on the Public Suffix List, so the site inherits nothing from Vercel and is treated as its own tiny site with weak brand signals. Ranking first for a commercial query in a country on a free subdomain, against Upwork, Freelancer, Clutch and Sortlist, is not realistic. A custom domain is the single largest strategic lever. **[DECISION: Yehia]**
5. **Only 8 indexable URLs, one language, no articles.** The search results for the target queries are dominated by marketplaces and job boards. An individual outranks them on long-tail commercial queries ("shopify developer cairo", "custom website design egypt", "speed up shopify store"), on the local pack, and on the person's name. That needs dedicated service pages, local content, and eventually a small set of evergreen articles. The site currently has none of these. Articles and Arabic were rejected earlier in the project; the new ranking goal is a reason to revisit both. **[DECISION: Yehia]**
6. **Keyword cannibalisation between `/` and `/services`.** In the uncommitted `dev` copy both pages target the identical phrase "freelance web developer in Egypt" in title, description and eyebrow. Google will pick one and suppress the other. Each page needs its own primary query.
7. **H1s carry no keywords.** Homepage h1 is the monogram "YA." plus a screen-reader-only name. Services h1 is "Websites that make your business more money." Projects h1 is "All projects". The keyword-bearing text is in `<p>` eyebrows and a hidden `<h2>`.
8. **Structured data is minimal.** Person schema uses a plain-string address, omits education, email, alternate names and an `@id`; there is no `WebSite`, no `BreadcrumbList`, no `Service` with `areaServed`, no `FAQPage`, and the five deep AI/ML case studies have no `TechArticle`/`SoftwareSourceCode` markup at all.
9. **Missing icon set.** Only `icon.svg` exists. `/favicon.ico`, `apple-icon`, and a web manifest all 404. Google and Bing show favicons in results and request `/favicon.ico` directly.

## 3. Technical SEO findings (T)

### T-01. Ship the uncommitted client-first work first (P0)

Everything below assumes the `dev` working tree is committed, merged to `main`, and redeployed. Until then Production advertises the wrong positioning. Per the repo rules: commit on `dev`, test on Preview, merge to `main`, then `git checkout main && git pull && git checkout dev && git merge main`.

After deploy, verify on the live origin (not locally) that `<title>`, `og:image` text, `robots.txt`, `sitemap.xml` all reflect the new copy. If a `NEXT_PUBLIC_*` value changes at any point, redeploy with "Use existing Build Cache" disabled (documented gotcha in `docs/implementation/phase-8-report.md`).

### T-02. Root metadata defaults are missing (P0)

`src/app/layout.tsx` sets only `metadataBase`, `title`, `description`. Add site-wide defaults so every route, including future ones and the 404, inherits correct social and robots metadata:

```ts
export const metadata: Metadata = {
  metadataBase: publicEnv.siteUrl,
  title: {
    default: "Yehia Alsaeed | Freelance Web Developer in Egypt",
    template: "%s | Yehia Alsaeed",
  },
  description: "...", // see C-02 for the shortened text
  applicationName: "Yehia Alsaeed",
  authors: [{ name: "Yehia Alsaeed", url: publicEnv.siteUrl.origin }],
  creator: "Yehia Alsaeed",
  publisher: "Yehia Alsaeed",
  category: "technology",
  formatDetection: { email: false, address: false, telephone: false },
  robots: {
    index: true,
    follow: true,
    googleBot: {
      index: true,
      follow: true,
      "max-image-preview": "large",
      "max-snippet": -1,
      "max-video-preview": -1,
    },
  },
  openGraph: {
    type: "website",
    siteName: "Yehia Alsaeed",
    locale: "en_US",
    url: "/",
  },
  twitter: { card: "summary_large_image" },
};
```

Notes:
- Once a `title.template` exists, child pages should export `title: "Services"` style short titles, not the full "X | Yehia Alsaeed" string, or the brand will double up. Update every page and the e2e title assertions accordingly.
- Add `openGraph.url` per page (only the case-study route sets it today) and `openGraph.type: "article"` only on case studies (already done there).
- Add `twitter.creator` / `twitter.site` only if Yehia has an X handle. Do not invent one.
- `og:locale`: `en_US` is the safe value for English copy. If Arabic pages are added (D-03), set `alternateLocale: ["ar_EG"]` and `alternates.languages`.

### T-03. Homepage canonical and sitemap disagree on the trailing slash (P2, cosmetic)

Canonical renders as `https://yehia-alsaeed.vercel.app` while the sitemap lists `https://yehia-alsaeed.vercel.app/`. Google normalises the root, so this has no ranking effect, but keep them identical. Simplest: leave Next's canonical as-is and emit the root sitemap entry as `origin` (no slash), or set the homepage canonical to `"/"` and confirm Next emits the slash. Either way, make the unit tests in `tests/unit/sitemap.test.ts` assert the chosen form.

### T-04. Favicon set is incomplete (P0)

Only `src/app/icon.svg` exists. `/favicon.ico` returns 404 (Google fetches this path directly for the SERP favicon and Bing does too), and there is no Apple touch icon or web manifest.

Add, using Next file conventions:
- `src/app/favicon.ico` (multi-size ICO: 16, 32, 48).
- `src/app/icon.png` at 192x192 and 512x512 (Next supports multiple `icon1.png`, `icon2.png` files with size metadata) or at least one 48x48-multiple PNG. Google requires the favicon to be a multiple of 48px for SERP display; SVG is accepted but a PNG fallback is safer.
- `src/app/apple-icon.png` at 180x180.
- `src/app/manifest.ts` returning name, short_name "YA.", `theme_color: "#2b3cff"`, `background_color: "#f1efe9"`, `display: "browser"`, and the 192/512 icons.
- The current SVG draws "YA." with `font-family: Arial`, which renders differently per platform. Convert the text to outlined paths (Archivo Wide 900, as in the header) so the icon is deterministic.

### T-05. robots.txt cleanup (P2)

Current output is correct. Optional tightening:
- Add `Disallow: /api/` (no indexable content there; keeps crawl reports clean). Keep `/_next/` allowed so Google can render.
- The `Host:` directive is Yandex-only and ignored by Google/Bing. Harmless; may stay.
- Do **not** block AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended). Being cited by AI answer engines for "freelance web developer in Egypt" is part of the goal. Optionally add an `llms.txt` at the site root summarising who Yehia is, services, location, and the canonical URLs (see C-09).

### T-06. Sitemap coverage (P1)

`src/app/sitemap.ts` lists the 8 routes. When new pages are added under this audit (service landing pages, articles, category hubs) each must be added to the static entries or derived from its content module, and `tests/unit/sitemap.test.ts` updated. Keep the "never fabricate `changeFrequency`/`priority`" rule; it is fine.

Optional: add `images` to case-study entries (Next supports `images: string[]` per sitemap entry) pointing at the Cloudinary URLs so the evidence screenshots enter image search.

### T-07. `/cv/Yehia_Alsaeed_CV_AI.pdf` is indexable (P1)

Google indexes PDFs. For a name query the PDF can outrank the homepage and it presents the recruiter framing to a client. Add a header rule in `next.config.ts` for `/cv/:path*`: `X-Robots-Tag: noindex, nofollow`. The file stays downloadable; it just stops competing with the homepage. Update `tests/e2e/cv-download.spec.ts` if it asserts headers.

### T-08. 404 page inherits the homepage title (P2)

`src/app/not-found.tsx` has no metadata, so a 404 response carries the homepage title and description. Give it "Page not found" as title and `robots: { index: false }`. The implementing agent should check the Next 16 docs for the supported mechanism for not-found metadata (a root `[...not-found]` catch-all page that exports metadata and calls `notFound()` is the usual pattern) and confirm the response is still a real 404 status.

### T-09. HTTP to HTTPS and future www handling (P1, verify)

Vercel redirects `http://` to `https://` by default; the probe from this network was intercepted by the ISP so it could not be verified. Verify from another network with `curl -I http://yehia-alsaeed.vercel.app/` and expect a 308 to https. When a custom domain is attached (D-01), choose apex or `www` as the one canonical host and configure Vercel to 308 the other and the `*.vercel.app` alias to it.

### T-10. Static rendering constraint (informational)

The design locks all public routes to static prerendering. Every recommendation below is compatible with that: metadata objects, `generateMetadata` reading from content modules, JSON-LD from server components, file-convention icons and manifest, and new static pages all prerender. Do not introduce `headers()`, `cookies()`, `searchParams` reads, or `generateImageMetadata` on public routes (the latter was already found to convert the OG route to dynamic; see `docs/implementation/phase-8-report.md`).

### T-11. `/projects?category=` filter URLs (P2)

The filter writes `?category=llm` with `history.replaceState`. These URLs return 200 with the full grid and the canonical `/projects`, so there is no duplicate-content problem. They also carry no SEO value. If category-level ranking is wanted for AI/ML (C-08), build real static pages rather than relying on the query parameter.

### T-12. Duplicate blocks between `/` and `/services` (P1)

The two service cards (`SERVICE_TEASERS` mirrors `SERVICE_OFFERS` verbatim) and the three client-work cards (`VISIBLE_CLIENT_WORK`, full contribution paragraphs) render byte-identical on both pages. Not a penalty, but it blurs which page should rank for Shopify queries. Recommendation: keep the full text on `/services` (the page that should rank for it) and shorten the homepage versions to one or two lines with a "Read more" link into the services page anchors. This also reduces homepage weight (three autoplay videos, see P-02).

### T-13. Internal linking and anchor text (P1)

- No internal link anywhere uses a keyword as anchor text; the nav says "Services", "Projects". Add a footer navigation block with descriptive anchors: "Shopify store development", "Custom website design", "Website fixes and speed-ups" (to `/services#fix`), "AI and machine learning projects" (to `/projects`), and the five case studies by name. Footers are crawled on every page and are the cheapest site-wide link boost.
- Case-study pages link only to previous/next/all projects. Add a short "Hire me" line linking to `/services` and `/#contact`, and a link back to the relevant category hub if C-08 is built.
- `/services` does not link to `/projects` or any case study. Add one line under "Every project includes" or in the FAQ ("See the engineering work") for crawl flow.
- The command palette links are client-side and invisible to crawlers; that is fine, they duplicate real links.
- `PageTransition` intercepts clicks but the anchors are real `<a href>` links, so crawlability is unaffected.

### T-14. Accessibility nit surfaced by Lighthouse (P2)

`label-content-name-mismatch` on the header logo link and mobile menu button. Change `aria-label="Yehia Alsaeed home"` to `aria-label="YA. Yehia Alsaeed, home"` (visible text must be contained in the accessible name) or drop the aria-label and use visually hidden text. Same for the menu button if its visible text differs from its label.

### T-15. Google Search Console and Bing Webmaster Tools (P0, Yehia action)

Not a code change but the highest-leverage item in this document:

1. Verify the Production origin in Google Search Console (DNS verification once a custom domain exists; until then use the HTML-tag method by adding `verification: { google: "..." }` to the root metadata, which renders `<meta name="google-site-verification">`).
2. Submit `https://<origin>/sitemap.xml`.
3. Use URL Inspection on `/`, `/services`, `/projects` and request indexing.
4. Repeat in Bing Webmaster Tools (it can import from GSC) and enable IndexNow if desired.
5. Check the "Pages" report after 7 days for "Discovered, currently not indexed" or "Crawled, currently not indexed". If the latter persists, it confirms the thin-signal problem that Sections 4 and 6 address.
